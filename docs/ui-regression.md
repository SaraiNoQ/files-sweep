# v0.3 界面修复

## 原因

v0.2 在 `searching` 时卸载整张 NSOutlineView，仅保留一个小进度控件。HSplitView 与各栏没有持续填满父容器的高度，根 VStack 又按子内容高度居中布局，导致筛选瞬间整体收缩。空间图重新出现时，还会把尚未加载的权重误显示为“没有项目”。

## 修复

- 根视图、分栏、各栏、表格区域与地图持续接受全部可用高度。
- 列表保持挂载，加载仅降低不透明度、暂停选择并在栏头提示，不改变骨架。
- 无搜索词的集合切换直接筛选，只有文字输入采用防抖。
- 地图区分未加载与真正空数据，避免空结果闪现。
- 左栏按实际裁剪区域重算名称列宽度，大小列固定宽度；不靠水平滚动才能看到体积。
- 左 270–300、右 280、中间自适应白色画布；浅灰矩形边框，选中时使用系统强调色。语言与目录栏头保持相同高度。

## 回归场景

在合成 developer-demo 样本上，检查文件与开发产物切换、语言筛选、搜索加载与无匹配、清除搜索、选中详情和地图下钻。确认顶边/底边位置不变，大小列可见，空结果不导致整页收缩。

额外验证原生 File 菜单、⌘O / ⌘S / ⇧⌘O、扫描保存与恢复；历史记录显示时间，开发候选项恢复后全部受保护。已在 macOS 15.3 上检查，其他系统仍需真机验收。

# 目录裁剪与小项目可读性修正（2026-10-25）

本轮依据用户标注修正目录右侧裁剪和过小空间块。上节视觉通过结论仅对应上一轮；本轮最终构建、重截和独立视觉复核已通过，证据见 `design-qa.md` 与 `design/qa/legibility-*.png` 补充。

- 目录表采用原生 plain 样式，取消自动内边距与单元格间距；固定 104 点大小列，名称列按可视宽度手动计算，并为纵向滚动条预留槽位，防止遮挡大小。
- 普通行 44 点、搜索行 54 点；文件夹使用 20 点实心图标与 medium 名称，图文间距 10 点、层级缩进 18 点，未选中行使用轻细分隔线。
- 上层最小高度从 210 点改为 280 点。主区布局矩形最小为 120×76 点；不可读项目及零字节项目移入独立放大区，明确显示“小项目已放大 · 面积非等比”。混合模式为小项目保留 112 点，168×64 点卡片横向滚动；全小项目使用最小列宽 168 点的自适应网格。
- 原始字节数不改写。`Treemap.layout` 继续等比；`readableLayout` 的主区保持剩余大项相对比例，但包含放大区的组合图不是全局等比。零字节尾项也保留汇总项；最多前 180 个子项与一个汇总，汇总本身不可下钻。
- 小项目可单击选中，目录可双击下钻；下方目录树继续提供对应的键盘入口。没有新增运行时配置、依赖或系统层，所有只读与隐私边界不变。

`testReadableTreemap` 覆盖接近 UInt64 最大值的极端比值、零字节、微小视口、181 项、项目无丢失/重复、主区最小尺寸与均衡数据的精确面积比例。最终检查输出为 28 组；最终界面验收及独立复核见 `design-qa.md`，不把源代码或 JSON 检查替代界面证据。

本轮最终验证：28 组核心检查通过；宽/紧凑窗口、零字节网格及局部对比见 `design/qa/legibility-*.png`。独立视觉复核为 ship，最新范围和缺口以 `design-qa.md` 为准。


# 地图筛选、分组与透明滚动条（2026-10-26）

用户取消滚动放大条。本节取代上两节的 Canvas、120×76 点主区与独立放大条约定；此前通过结论仅属于对应历史版本，本轮构建、测试及最终界面复核仍待完成。

- 地图仅纳入当前目录的子目录与严格大于 10 MiB 的普通文件；等于 10 MiB、小文件、链接和其他类型排除，零字节目录保留。地图无滚动条；页脚显示“文件夹及 > 10 MiB 文件 · 面积设有下限，非等比”。
- 按大小升序分行，原始布局矩形至少 144×76 点；先满足下限，再按权重分配剩余宽高。有空间且最大项超过总量一半时放在末行。可见按钮各边内缩 2 点；底层等比 `Treemap.layout` API 仍保留。
- 当前目录全部合格子项参与规划，不预先截断 180 项。每次最多渲染 180 个原生 SwiftUI Button，并受窗口容量限制；最小前缀合并为可进入分组，组内适度溢出仍合并最小前缀、其余单项直接展示；仅当项目数超过当前容量的两倍时采用均衡子组，避免百万项尾部逐项下钻。范围保留原始绝对索引和字节合计；提供“上一级分组 / 返回目录”。
- 地图布局按目录、快照代次、分组范围与尺寸异步缓存，悬停不再次排序完整列表。目录继续 AppKit 行复用，未新增依赖或运行时配置。
- 目录与详情仅使用标准 NSScroller，不自绘滑块。目录在 setter、挂入窗口和布局时保持 scroll view 与实际纵向滚动条为 `.overlay`。详情内容内的 `TransparentScrollbars` 标记仅配置自身 `enclosingScrollView`，同时检查 scroll view 和实际纵横滚动条的 overlay 模式，并关闭 scroll/clip view 背景绘制；无整窗遍历或全局偏好修改。之前的 `ClearTrackScroller` 尝试已移除。目录关闭自动尺寸调整，由布局按实际 clip 宽度减去系统 overlay 滚动条宽度预留空隙，再保留固定 104 点大小列，避免遮挡。地图自身不加入 ScrollView。

`testReadableTreemap` 已更新为筛选阈值、极端数值范围、矩形无重叠与满覆盖、最小尺寸、万项分组及子组范围/字节保持、全零目录、微小视口及 33 项在 18 槽位时“首项汇总、其余单项”、在 6 槽位时均衡为 6 组且每组不超过 6 项的检查；本轮 28 组检查的最终结果及界面证据待补充。元数据只读、权限与统计不确定性、历史保护及 LLM 发送边界不变。

恢复解锁后的原生界面检查已观察分组路径 33→10→33→根目录，紧凑根视图自动合并 43 项。目录运行时辅助功能标识 `FileSweep.directory.1.1` 证实 scroll view 与实际滚动条都为 overlay；`design/qa/overlay-proof-wide.png` 显示目录无白轨道。详情在紧凑窗口的旧构建仍显示白条，最新显式设置实际滚动条的修正待重截；其诊断标识为 `FileSweep.transparent.1.1`。核心检查仍为 28 组，本次未修改核心逻辑；最终界面验收仍待完成，以 `design-qa.md` 后续证据为准。

# 详情滚动条样式稳定性（2026-10-28）

修复详情滚动条偶发恢复白色传统轨道的问题。原 `TransparentScrollbars` 只在更新或入窗后异步配置一次，不能持续约束 SwiftUI 内部滚动视图。详情改为持有原生滚动容器，并与目录树共享既有 overlay setter、入窗与布局约束；继续使用系统 NSScroller，不自绘、不 swizzle、不修改全局滚动条偏好。

详情内容宽度跟随 clip 区，SwiftUI 父环境和动画事务继续传入，包含禁用状态与辅助功能设置。相同项目刷新保留位置，换项目回顶；底部进入目录和 Finder 操作仍在滚动区外。

`scripts/check-scrollbars.sh` 使用隐藏原生窗口验证强制 legacy、实际 scroller 替换、系统样式通知、透明背景、移入移出窗口、项目切换、长短内容、窄宽布局与禁用状态。滚动条检查和既有目录回归通过。没有调用 Computer Use，也未改变系统设置；真实鼠标/触控板交替与 macOS 13 实机仍未验证，不声称视觉验收。


# 上线前状态收尾（2026-10-29）

AI 结果与读取问题复用 `PaperScrollView`（原详情容器），统一 overlay 与透明 scroll/clip 背景。合成超长回复在强制系统 legacy 后仍保持 overlay；错误和重试成组显示，未启用只保留一处状态，取消后手动重新判断。设置保存使用原生 Return 默认动作；不更改数据发送、取消、保护或默认监听策略。
