# AI 解释边界

用户确认：自填兼容 API 服务与密钥。v0.1 只有本地脱敏预览，无网络客户端，不收集密钥。

## 未来接入的固定边界

- 默认关闭，服务地址、模型和密钥由用户设置。密钥只进入 macOS Keychain，不放 UserDefaults、日志或项目文件。
- 必须先确认具体协议。初步考虑 OpenAI-compatible Chat Completions；“兼容”不保证各服务字段、流式格式和错误行为完全相同。
- 云端地址要求 HTTPS；本机模型只允许显式配置的 loopback 地址。拒绝携带用户名密码的 URL；发送凭据时不自动跟随重定向到其他主机。
- 每次展示将发送的真实载荷与目标主机，用户明确确认才请求。扫描、选中项目和输入搜索词均不触发上传。
- 请求只包含类型、粗粒度体积、有限的结构别名、白名单名称线索、本地判断及缺失信息。精确路径、任意名称、原始时间、内容、环境变量、Git remote、xattr、凭据均不进入模型上下文。
- 名称线索不是语义事实。`target` 只能生成“可能的构建目录”提示，不能变成“可以删除”。脱敏不等于绝对匿名；结构和技术栈仍可能敏感。
- v0.1 `ExplanationContext` 是白名单构造，不对原始树做字符串替换后直接发送。子项上限 20，使用本次临时 item-N 别名。
- 模型输出当作不可信文本。固定展示“解释、缺失证据、人工检查建议”；不执行命令、不渲染可执行 HTML，不读取模型提出的路径，不自动继续收集数据。
- 本地保护等级优先。模型不能降级未知/受保护项，不提供删除许可。
- 超时、取消、断网和服务失败不影响本地扫描。限制请求/响应长度和并发；不得后台自动重试导致重复披露或计费。
- 对话不默认持久化；日志不含凭据、载荷、原始文件名或模型正文。服务端保留政策取决于用户选定服务，界面不能声称“零保留”。

## 交互

选中项目 → AI 风险解释 → 未配置时配置服务 → 预览实际脱敏信息与接收方 → 本次确认 → 解释。

设计线框的按钮只模拟该流程，始终显示演示状态。原生程序的预览不会发送请求。
