# 开发期间闪退分析与修复

分析日期：2026-10-25。读取本机两份 FileSweep 诊断，仅归纳终止原因，不复制完整诊断或个人路径。

## 已确认的证据

- `FileSweep-2026-10-25-200337.ips`：CODESIGNING / Code 2 / Invalid Page，SIGKILL (Code Signature Invalid)。
- `FileSweep-2026-10-25-201923.ips`：相同终止原因，触发线程正在处理 SwiftUI/AppKit 菜单更新。
- 异常类型虽包含 EXC_BAD_ACCESS，终止命名空间明确指向代码签名检查；不能仅凭 SwiftUI 栈归因为普通内存越界。
- 旧构建脚本直接 cp 到已部署的可执行文件，再在同一包上重签，可能改写正在运行或被内核缓存签名的文件。

日志与该更新路径符合 Apple 描述的签名缓存失效问题：[Updating Mac Software](https://developer.apple.com/documentation/security/updating-mac-software)。该文档要求替换文件而非原地修改，并建议用 inode 检查更新行为。

## 发布修复

先在独立目录构建、签名、验证新包，再用 macOS RENAME_SWAP 原子替换整个包。首次发布使用 rename。旧包保留在 `dist/.previous-build-*.app`，不原地改写旧可执行文件，不立即清除仍可能被进程使用的资源。

`check-publish.py` 验证打开的旧文件仍读到原字节、旧 inode 保留、新路径呈现新文件。实际在旧应用运行时发布新包并打开 File 菜单，旧进程仍正常响应；之后正常退出并启动新版本。没有关闭签名检查、SIP 或 Gatekeeper。

## 额外稳定性修复

- 扫描会话与快照代次隔离，取消/过期回调不能覆盖新根。
- NSOutlineView 旧 item、选择、下钻和 Inspector 在索引变化时检查边界，更新期间抑制旧选择通知。
- Treemap 权重绑定快照代次，避免旧权重索引新数据。
- 极大/极小文件混合时，浮点相减会丢失剩余权重；对子区间重新求和，测试确保坐标有限。
- 聚合溢出返回错误，不触发整数 trap。
- 关闭窗口取消任务并释放监听；历史或过期数据维持保护状态。

这些是针对新增异步更新路径的防护，不声称它们造成了上述两次已记录闪退。

## 验证范围

27 组核心与真实 FSEvents 检查通过，发布检查及新包严格签名验证通过；原生界面已验证更新中搜索、选中对象消失、暂停与恢复。检查仍只有上述两份应用诊断。不能据此保证消除了所有尚未出现的崩溃；其他系统、磁盘和长期压力仍需验收。
