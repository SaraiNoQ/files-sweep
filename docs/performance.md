# 扫描性能验证

日期：2026-10-25。环境：arm64、macOS 15.3、Swift 6.1.2，Release 构建。二进制 deployment target 已检查为 macOS 13.0，SDK 15.5。

## 最终记录

| 样本 | 条目（含目录和边界样本） | 扫描中位数，3 轮 | 识别中位数 | 系统 du 中位数 | 最大进程 RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 10 万文件 | 100,106 | 0.178 秒 | 0.031 秒 | 0.169 秒 | 36.9 MiB |
| 100 万文件 | 1,001,005 | 7.416 秒 | 0.319 秒 | 7.156 秒 | 236.6 MiB |

原始记录：`benchmark-100000.json`、`benchmark-1000000.json`，现为 v0.2 复测，RSS 包含识别阶段。报告包含每轮数据，不只挑最快的一次。不同缓存/负载下早期结果不同，不把本轮变化归因于扫描器提速或内存优化。

识别阶段在既有快照上运行 22 条开发规则，没有新增文件系统读取。百万样本为无候选的普通文件，故该时间测量规则过滤与保护聚合开销；不代表复杂开发目录的最坏耗时。实际规则命中与保护行为由独立样本验证。

合成样本每目录 1000 文件，大多数为空，每 16 个写入 128 字节，另有 2 GiB 稀疏文件、一个硬链接和目录符号链接。分配空间与 `du -sk` 每轮完全相同；条目数也通过断言。10 万样本被 Finder 添加了一个 `.DS_Store`，报告明确计入该额外元数据文件，而不删除它或忽略统计差异。扫描器不读取文件内容。

这是**缓存状态未控制的合成实验，不是冷缓存、真实全盘或 SSD 吞吐承诺**。没有清空系统缓存。du 不保留可搜索目录树，不能直接把差值解释成遍历器优劣。当前环境未安装 fd/dua，未进行它们的实测。

## 实现选择

使用系统 Darwin fts（PHYSICAL / XDEV / NOCHDIR），不跟随目录项符号链接、不隐式跨卷。单遍采集和聚合，紧凑的父/子/同级索引保留在 Swift 数组中。只对多链接对象保留文件身份集合，避免所有文件都进入哈希表。

该成熟系统接口在当前样本上接近 du，满足首轮端到端验证。没有为了“可能更快”新增线程池或重写 getattrlistbulk 二进制解析器；后者需要更复杂的结构对齐、属性缺失与文件系统兼容性处理。未来优化由同口径性能证据驱动，不以语言切换作前提。

## 正确性与交互验证

`filesweep-checks` 在 Debug 下运行 14 组断言检查：原有树聚合/链接/取消/权限/脱敏/空间图检查，加上 22 条规则命中、伪装名称与符号链接标记、保护向上传递、部分扫描保护、仅使用快照、默认路径结构与用户范围、混合工具链归属歧义及嵌套候选不重复计数。

v0.3 新增 4 组扫描记录检查，总计 18 组；详见 `scan-archives.md`。百万条目 SQLite 往返测得保存 1.25 秒、读取 1.85 秒、文件 46.6 MiB；`benchmark-archive.json` 保留原始单次结果。该次是合成样本、缓存状态未控制，不与上表三轮中位数混算。

v0.4 总计 27 组，增加真实 FSEvents、增量合并、权限恢复、根移动、硬链接与极端地图比例检查。独立的 `benchmark-incremental.json` 包含 1,001,006 条目：只重扫一个目录，局部更新 0.211 秒，初始完整扫描 7.741 秒，根统计与完整重扫一致。进程峰值 RSS 约 370 MiB，包含比较时同时保留的多个快照；不是纯增量更新状态的内存。缓存与系统负载未控制，不作为固定倍数承诺。

本机只有 Command Line Tools，未安装 XCTest。因此用独立的 Swift 断言检查可执行文件，不引入测试库。必须 Debug 运行；Release 会移除 assert。

原生应用已实际启动。v0.1 验证了文件名搜索、结果详情联动、目录展开、下钻、清除搜索及脱敏预览。v0.2 使用项目内合成样本验证三栏布局、开发产物列表、同名目录区分、保护原因、Java 语言筛选和匹配保护计数；LLM 入口已收起。没有发出 AI 网络请求，也没有把个人文件名写入基准记录。

## 尚未验证 / 已知边界

- macOS 13/14 与 26+ 真机；当前仅在 15.3 上运行，构建工具尚无 Liquid Glass SDK。
- 冷缓存、真实全盘、网络盘、外置盘、云文件提供者、超深目录及大量并发改动。
- 扫描是实时遍历，不是文件系统一致性快照。用户选择的根目录的祖先路径可能由系统别名解析；根目录自身符号链接被拒绝，遍历过程中不跟随符号链接。
- fts 的一次系统调用无法抢占；取消在下一次返回后响应，慢/失联文件系统可能延迟。尚未实测中途取消的最坏延迟。
- APFS 克隆/快照共享块未去重；硬链接分配空间只计入第一次遇到的位置。该口径不预测实际回收量。
- 目录树展开时仍同步排序当前分支；百万个直接子项等极宽目录的 UI 响应还需专门测量。搜索前 500 项显示，统计全部匹配数；尚无持久索引、文件内容搜索或路径表达式。
- 完成或停止扫描后发布目录树；扫描中仅有进度，不发布增量树。
- v0.3 保存/恢复是显式完整元数据快照；v0.4 的 FSEvents 更新仅作用于当前打开的实时扫描，不提供跨启动自动索引恢复。历史数据不能当作实时状态。
- 样本目录在 `.bench-fixture`，被 Git 忽略，约 269 MiB 实际占用（稀疏文件使逻辑体积看起来更大）。保留用于用户复验，不混入产品包。


## 2026-10-28：UI 玻璃合成与环图重绘


同一台机器、同一 1240×760 内容区、同一合成快照，共 170 个扇区。通过内存 NSEvent 切换悬停，强制布局并读取窗口内容位图；预热 8 次，记录 40 次。两次均为 -O 编译的 UI 与相同 Debug 核心对象。

| 离屏更新与位图读取 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 中位数 | 856.26 ms | 15.42 ms |
| P95 | 867.35 ms | 16.17 ms |

这包含位图读回成本，不是屏幕帧率，也不证明 GPU 调用、GPU 利用率或真实鼠标到屏幕的延迟。运行时没有可供采样的 FileSweep 进程；没有启动、关闭或向用户窗口注入事件。

主要修改：共享玻璃面改为不透明纸色与高光，移除嵌套实时模糊及面板/地图投影；环图使用两个 Canvas 分开静态底图和局部高亮，静态底图按布局键复用，不对悬停/选择启动整图动画。保留工具栏系统材质与小控件按压反馈。详情操作条和六个图例的独立玻璃底删除。

目录树名称列与展开符号一起右移 12 点，大小列不变。未变化的选择不重复展开祖先、未变化的行高不重复设置；可见区域跟踪对象不随布局重建。

复跑当前实现：`sh scripts/benchmark-ui.sh after`。`before.json` 是修改前测量记录，`after.json` 是最终实现记录；脚本标签只命名测量，不恢复旧源码。原始逐次值包含在 JSON 中。

回归：`sh scripts/check-outline.sh`、`sh scripts/check-sunburst-input.sh` 通过，覆盖目录左留白、大小列、折叠保持、选择、搜索结果替换、跟踪复用、扇区输入和快照代次。实际内容离屏图见本目录 PNG；未验证真实标题栏、屏幕 FPS、GPU 轨迹、VoiceOver 或 macOS 13 实机。
