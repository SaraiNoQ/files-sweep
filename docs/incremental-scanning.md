# 自动增量扫描 v0.4

2026-10-29 起，新窗口默认关闭自动更新。选择目录和手动重扫只执行一次扫描，不创建监听；需要时通过工具栏的“开启自动更新”主动启用。启用后先监听，再修复未观察期间的原范围变化；本窗口后续扫描继续遵循用户选择的开启/关闭状态。打开历史记录不监听、不自动访问原路径；手动重扫后才能启用。

已开启自动更新时，先创建 FSEvents 监听，再执行初始只读扫描，避免漏掉扫描期间的变化。

## 更新流程

1. 文件事件映射到父目录；递归失效事件保留其目录范围。
2. 合并重复或互相包含的范围，约 0.5 秒安静期后更新；连续事件最多等待约 2 秒后尝试，已有任务运行时只积累下一批。
3. 重扫变化目录，其他子树复用内存元数据，再重建标识、子节点索引、聚合大小和开发规则结果。
4. 硬链接按设备/inode 在整个合并结果中去重，不能只在局部扫描计数。
5. 新快照以新代次发布。选择与下钻位置按路径重新定位；消失的选中项清空，下钻目录消失则回退到仍存在的父目录。

变化待处理时，候选项临时受保护。刷新完成前不宣称旧数据是当前状态。更新时仍可浏览和搜索，过期搜索不能覆盖新快照。

## 恢复与边界

- 用户/内核丢失事件、事件标识回绕、挂载变化、过多范围，或原扫描不完整时，重扫原选择的根目录。
- 根目录直属条目变化也可能需要完整根扫描。局部文件系统 I/O 不代表 CPU 全部局部化：紧凑树与规则仍做 O(n) 内存处理。
- 暂停停止监听与当前更新。恢复先监听，再完整修复原范围，补齐未观察的变化。
- 根目录设备/inode/解析后位置变化，或收到根变化通知时停止，不追踪到新位置。
- 局部范围不跟随符号链接或跨卷；范围祖先检查和扫描前后身份复核发现变化时拒绝发布。持续变化的文件系统仍不是原子快照。
- 读取失败保留不完整状态并暂停自动更新，避免无法读取的目录使每个事件都触发完整重扫。权限恢复后可手动刷新或恢复监听，修复原范围。无法安全继续时保留旧结果并标为待核验，不以空目录替换。
- 关闭窗口取消扫描/搜索/刷新并释放事件流；没有常驻服务或跨启动自动扫描。
- 单次文件系统调用不能强制抢占。网络盘、云提供者和其他 macOS 版本尚未实机验收。

## 验证

27 组检查覆盖局部/完整扫描对照、目录删除和符号链接替换、跨范围硬链接、权限失败及恢复、取消与根替换、事件标志和路径别名、真实文件事件、停止回调、短生命周期监听及真实根移动。

原生应用验证了新增文件自动出现、体积增加、选中文件删除后清空选择、暂停与恢复。发布期间旧应用仍运行，旧进程菜单可以响应，未发现新增 FileSweep 崩溃记录。

百万条目合成基准原始数据见 `benchmark-incremental.json`：只向生成的 project-0000 子目录加入一个自建文件，局部更新后与完整重扫比较根计数、逻辑大小和分配空间。文件由基准程序自行移除，不接触个人目录。该数据不是冷缓存或跨设备性能承诺。
